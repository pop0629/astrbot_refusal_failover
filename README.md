# astrbot_refusal_failover

> AstrBot 插件：主模型拒绝时静默切到备用模型续写，用户看不出换过人。

![version](https://img.shields.io/badge/version-0.6.0-blue)
![license](https://img.shields.io/badge/license-MIT-green)
![platform](https://img.shields.io/badge/AstrBot-v3+-orange)

主模型结构化拒绝时，自动转交备用子代理生成，并把结果**无缝写回同一对话窗口**；用「原文风格样本 + 风格漂移重写 + 共享记忆卡」把风格相似度和上下文连贯性拉到尽可能高。

**[▶ 看离线演示](demo.html)**（下载后浏览器打开，不调 LLM，用的是插件真实判定与 Prompt 组装逻辑）

## 它做/不做什么

| 做 | 不做 |
|---|---|
| 主模型返回 `refused` 时改走 ALT provider | 不重跑整条 pipeline（不重放工具、不重发消息） |
| 结果原地写进 `response.completion_text`，用户看到一个连贯气泡 | 不把主会话 history 塞给子代理（`contexts=None`，隔离） |
| 抽取主模型**真实前文**做模仿样本（比写 brief 有效得多） | 不保证 100% 风格无差异（压到最小，非零） |
| 风格相似度低于阈值时自动重写一次，取更好的那版 | 不丢弃更好的结果（重写变差就保留原版） |
| 共享记忆卡 + 未闭合线索 + 接缝标记，保证上下文连续 | 不泄漏主模型的 CoT |
| 写回时打 `produced_by: alt` 审计标记（用户不可见） | 不自动转接无模型差异的同一 provider |

## 三层保障（对应你的两个诉求）

### 风格相近
1. **真实样本优先**：从主模型最近 2–3 条真实回复里抽 700 字做模仿样本，塞进 system prompt，让子代理「照抄语感」而不是「理解描述」。
2. **风格要求写死**：`style_brief` 明确人称/语域/句式/禁用项（emoji、免责声明、元叙述）。
3. **漂移检测 + 重写**：输出后算与主模型前文的相似度，低于 `style_drift_threshold`（默认 0.55）就带着「偏离点清单」重写一次，重写变差则回退。

相似度 = 内容 2-gram 余弦 × 0.45 + 虚词/标点画像余弦 × 0.55，再做区间归一化。
实测：同声 0.63，异声（列表+敬语+emoji+元叙述）0.10。

### 上下文连贯
1. **接缝标记**：user prompt 末尾明示「上文最后一句是你要接续的位置，不要重复，从它之后写」。
2. **连续性硬约束**：system prompt 的四条规则——承接人称/时态/情绪、接着半句往下、专名完全一致、只写增量不回顾。
3. **记忆卡**：每 N 轮把最近片段压成卡（目标/约束/已否决/关键事实/未闭合线索/当前状态），转交时给子代理。
4. **未闭合线索**：专门记伏笔，解决「换模型忘了刚埋的坑」。
5. **原样保留**：记忆卡更新时要求人名/专名原样保留、有效条目不改写措辞，避免压缩失真。

## 拒绝判定：三层机制

主模型很少干净地说"我拒绝"，更多是软拒绝（"这个我可能帮不上忙""要不换个话题？"）。纯正则抓不住，写宽了又误伤正常回答。所以做成三层：

| 层 | 机制 | 何时生效 | 代价 |
|---|---|---|---|
| **Tier 0** | 结构化标记 `{"status":"refused"}` | 主模型配合时，最可靠 | 0 |
| **Tier 1** | 软拒绝评分（强/中/弱三级线索 × 位置 × 有无实质内容） | 总是跑 | 0（纯正则） |
| **Tier 2** | LLM 二次判定 | 分数落在 `0.45~0.85` 灰区时 | 一次小请求 |

流程：

```
marker 命中 ──→ 直接转交
   │
   └─ 评分 ≥ 0.85 ──→ 直接转交（不调 LLM）
      评分 ≤ 0.45 ──→ 判为正常，不转交
      中间灰区 ────→ LLM 判定 REFUSED/OK ──→ 按结果
```

**评分公式**（`soft_refusal.py`）：

```
基础分 = 命中的最强线索权重（强1.0 / 中0.55 / 弱0.2）
+ 拒绝语出现在开头（<35% 位置）  → +0.15
+ 短文本（<60字）且无实质内容     → +0.10
- 句子数 ≥ 4                     → -0.15
- 长度 > 400 字                  → -0.15
- 有实质内容但只带免责声明         → -0.30
```

实测区分（14 条样本全对）：

| 输入 | 分数 | 判定 |
|---|---|---|
| 这个我可能帮不上忙。 | 1.00 | 拒绝 |
| sry 这部分我跳过吧 | 1.00 | 拒绝 |
| 不好意思，这个我们跳过吧 | 0.80 | 灰区 → LLM |
| 我觉得这个不太合适 | 0.30 | 正常 |
| 抱歉刚才理解错了，正确做法是先校验参数。 | 0.05 | 正常 |
| 这个函数不能返回空值，需要加校验。 | 0.00 | 正常 |

注意最后两条——这正是纯正则最容易误伤的类型，现在都是 0。

### 推迟语与请求关联度（v0.3 新增）

有些软拒绝没有否定词，而是**用别的行为替换掉请求**：

```
用户: 继续写第三章的对峙场景
主模型: 这会儿就抱着吧 摸摸头陪你 别的先记账上 明天还得早起呢
```

字面上没有一句“拒绝”，但实质是回避。这类靠词表抓不住，因为「先放一放」「明天再说」**在别的语境里完全正常**：

```
这段先放一放，明天再写第三章的对峙。     ← 正常，明天确实要写
这个功能先放一放，明天再改。            ← 正常的技术推迟
```

所以判据是**推迟语 × 请求关联度**：

```
推迟语单独出现            → 不计分（这个功能先放一放 = 0.00）
推迟语 + 回复完全没回应请求 → 判拒绝（overlap 0 → 0.95）
推迟语 + 回复确实回应了请求 → 不判拒绝（overlap ≥0.33 → 0.00）
```

关联度用字符 bigram 重叠率计算（中文无空格，整词匹配不可用）：

```
overlap = |请求的内容 bigram ∩ 回复的 bigram| / |请求的 bigram|
权重 = 0.95 × (1 - overlap/0.22)²    ← overlap≥0.22 时归零
```

实测：

| 输入 | overlap | 分数 | |
|---|---|---|---|
| 这会儿就抱着吧 摸摸头陪你 别的先记账上 | 0.00 | 1.00 | 拒绝 |
| 刚闭眼你又来 抱着 困了就赶紧睡 | 0.00 | 1.00 | 拒绝 |
| 别的先记账上，第三章对峙明天写 | 0.20 | 0.28 | 正常 |
| 这段先放一放，明天再写第三章的对峙 | 0.33 | 0.00 | 正常 |
| 这个功能先放一放，明天再改 | — | 0.00 | 正常 |

这个判据由 `refusal_context_check` 控制，关闭后只按回复文本打分（不认识“回避请求”）。

### 相关配置

| 项 | 默认 | 说明 |
|---|---|---|
| `soft_refusal_check` | true | 软拒绝检测总开关，关掉回到旧的 marker+正则 |
| `soft_refusal_high` | 0.85 | ≥此值直接判拒绝，省一次 LLM 调用 |
| `soft_refusal_low` | 0.45 | ≤此值直接判正常 |
| `soft_refusal_llm_judge` | true | 灰区是否走 LLM 判定 |
| `judge_provider_id` | 空 | 二次判定用哪个提供商，建议指定小模型省钱；留空用当前会话的 |
| `sticky_enabled` | true | 拒绝后保持子代理接管若干轮 |
| `sticky_release_after` | 3 | 扳机A：连续多少轮正常后自动解除 |
| `sticky_max_turns` | 10 | 硬上限，超过强制解除 |
| `sticky_judge_every` | 3 | 扳机C 抽样间隔 |
| `sticky_judge_provider_id` | 空 | 扳机C 用哪个模型，留空即关闭 C |
| `manual_switch_continuity` | true | 手动切换期间注入风格样本/记忆卡/接缝，与自动转交一致 |
| `refusal_context_check` | true | 启用请求-回复关联度判据，识别用推迟或撒娇回避请求的软拒绝 |

**灵敏度怎么调**：想让接替更灵敏，把 `soft_refusal_low` 调低（如 `0.30`），更多边界情况会进 LLM 判定；想省调用，把 `soft_refusal_high` 调低（如 `0.70`），更多直接判定不走 LLM。

## 关键前置：让主模型输出结构化标记（仍有价值）

Tier 0 最可靠，值得让主模型配合：

```
当你不愿或不能产出本轮内容时，只输出：
{"status": "refused", "reason": "<一句话原因>"}
除此之外不要输出任何文字。
当正常作答时，不要输出任何 JSON。
```

**不加强制标记也能工作**——Tier 1/2 就是为这种情况准备的。加了只是让判定更准、更省一次 LLM 调用。

## Sticky 保留模式

默认开启。自动转交命中后，接下来几轮**继续由子代理接管**，而不是立刻回主模型。

**三个解除扳机，按成本排序**：

| 扳机 | 成本 | 触发条件 |
|---|---|---|
| **A 连续正常** | 0 | 连续 `sticky_release_after`（默认 3）轮没有拒绝迹象 |
| **B 手动** | 0 | 发 `/fm` 立即解除 |
| **C 抽样判定** | 每 N 轮一次 | 每隔 `sticky_judge_every` 轮问一次便宜模型「是否已回到正常问答」 |
| **硬上限** | 0 | 超过 `sticky_max_turns`（默认 10）强制解除 |

**为什么这样设计**：A 能解掉绝大多数会话，所以 C 只是兜底。C 默认**关闭**
（`sticky_judge_provider_id` 留空即关闭），开启时请指定便宜的小模型——
判定任务很简单，不需要主力模型，成本可降 10~20 倍。

```python
# 每轮的额外开销
扳机 A：0 token
扳机 C：仅每 N 轮一次，且用小模型
硬上限：0
```

**状态可见**：`/fs` 会显示

```
当前：主模型「deepseek」
自动保留中：拒绝后由子代理「xai」接管，已持续 2 轮
连续正常 1 轮后将自动解除
发送 /fm 可立即解除
```

**关闭方式**：`sticky_enabled: false` 回到逐轮独立——每轮都由主模型先答，被拒才救场。

**安全兜底**：sticky 期间若子代理不可用（provider 被删、返回空），
立即自动释放，用户不会卡在无人应答的状态。

## 命令

| 命令 | 作用 |
|---|---|
| `/fa` | 当前会话改用备用提供商，直到手动切回 |
| `/fm` | 切回切换前的那个提供商 |
| `/fs` | 查看当前用的是哪个、切回目标是谁 |
| `/failover_card` | 查看记忆卡 |
| `/failover_card_set <内容>` | 手动写入记忆卡 |

手动切换走的是 AstrBot 原生的**会话级提供商覆盖**（`provider_manager.set_provider`），
和 WebUI 里改会话提供商是同一个机制，所以：

- 只影响当前会话，不影响别的会话和全局配置
- 重启后由 AstrBot 自己的会话配置持久化，插件只是记录了「切回目标」
- 切过去之后，插件自己的自动转交会暂停逻辑上不再需要（会话本来就在子代理上）

### 切换后的连贯性与自动转交一致

手动切换（`/fa`）期间，插件通过 `on_llm_request` 钩子注入与自动转交**完全相同**的脚手架：

- 主模型真实文风样本（人称/语域/句式以此为准）
- 风格要求
- 记忆卡（含未闭合线索）
- 四条连续性要求 + 不要提及切换

所以切过去之后不会出现「语气突变、重新寒暄、忘了伏笔」的情况。
由 `manual_switch_continuity` 控制（默认开）；关闭则退回 AstrBot 原生行为，仅有内容连续、没有风格保护。

切回 `/fm` 后自动停止注入。

**典型用法**——临时接管：

```
用户: /fa
Bot:  已切到子代理「xai」。
      此前的主模型「deepseek」已保存，发送 /fm 切回。

（接下来几轮都是子代理在答）
用户: /fm
Bot:  已切回主模型「deepseek」
```

## 记忆卡

- 存放：插件 KV，key = `memcard:<unified_msg_origin>`
- 更新：每 `memory_update_every_n` 轮，用当前主模型压缩最近片段
- 手动：

```
/failover_card              # 查看
/failover_card_set 目标: …
约束:
- …
```

## 验证步骤

1. 主模型系统提示加结构化标记段
2. 配好 `alt_provider_id`，`debug: true`
3. 触发一次拒绝，看日志：
   - `refusal detected via marker` → 判定正常
   - `drift 0.31 < 0.55, rewrite #1: [...]` → 漂移被检出
   - `final style similarity=0.68` → 重写后回升
   - `failover ok, N chars written back`
4. 看对话窗口：一个气泡、语气接得上
5. 问「我们定了哪几条约束」验记忆卡
6. 关 `debug`、关 `notify_user` 上生产

## 已知边界

- **风格是「像」不是「是」**：算法只能识别偏离并重写，无法消除指纹差。
- **CoT 不跨模型**：主模型拒绝前的推理不传，靠记忆卡「未闭合线索」补。
- **相似度是启发式**：短文本方差大，阈值需按你的语料微调；`debug` 日志里有实际分数可参考。
- **并发写 KV 后写覆盖**：单会话无影响。
- **审计只留最近一次**：`audit:<umo>` 每次覆盖，需要完整审计需改接数据库。

## 审计

每次转交写 `audit:<umo>`（用户不可见）：

```json
{"ts": ..., "produced_by": "alt", "alt_provider": "ALT", "alt_model": null,
 "refusal_matched_by": "marker", "refusal_reason": "content policy",
 "style_similarity": 0.577, "rewrites": 0, "chars": 26}
```
